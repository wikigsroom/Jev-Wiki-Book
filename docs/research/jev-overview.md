# Jev：原理、作用与适用场景

> 调研日期：2026-09-19
>
> 本文说明 TypeSafe Jev 的产品范式，不代表其原始权重已开源。当前 JEV 项目使用本机运行的社区 NanoJev 复刻；实现、限制与验证见 [README](../../README.md) 和 [本地评测](../../evals/README.md)。

## 一句话定义

Jev 是 TypeSafe AI 面向软件自动化推出的结构化决策模型。它不负责写文章、代码或聊天，而是接收一段状态和预先定义的问题，返回程序可以直接使用的选择、评分、概率和置信度。

官方介绍：[TypeSafe AI](https://typesafe.ai/)、[Introducing System One Models and Jev](https://typesafe.ai/blog/introducing-system-one-models-and-jev)。

## 原理

传统大语言模型通常逐 token 生成字符串；软件还需要解析字符串、校验格式，再决定下一步。Jev 把输出空间限制在调用者事先定义的类型中，让模型直接回答“应该选什么、分数是多少、是否成立”。

核心输入输出：

```text
程序状态 + 结构化问题
        ↓
       Jev
        ↓
选项 / 评分 / 是或否概率 + 每个答案的概率与置信度
        ↓
普通代码根据阈值执行、转人工或继续调用大模型
```

主要问题类型：

- Choice：从预定义选项中选择一个；
- Score：按预设量表打分；
- Noul：判断一个命题是否成立，返回 yes 的概率。

多个问题可以针对同一状态并行评估，因此适合大量重复、边界清晰的判断。它不会生成开放式文本，所以不会自由编造预设选项之外的回答；但“输出合法”不代表“判断一定正确”，置信度也不是事实保证。

## 作用

Jev 主要替代软件流程中那些“需要理解语义，但不需要写长文本”的大模型调用：

- 将自然语言请求分类并路由到部门、工具或工作流；
- 判断优先级、风险、是否需要人工介入；
- 对候选项排序或评分；
- 判断内容是否相关、安全、完整或符合规则；
- 判断一个 Agent 是否已经完成任务、下一步该调用什么工具；
- 在大量重复任务中进行低延迟、低成本的批量判定。

比较理想的工作方式是：Jev 负责判断，普通代码负责阈值、权限、状态修改和副作用；需要解释、写作或生成代码时，再交给 Claude、GPT 等生成式模型。

## 典型场景

### 1. 工作流路由

例如把客户消息分为退款、技术支持、投诉或销售，并根据置信度决定自动分派还是转人工。

### 2. Agent 决策

例如从搜索、读取文件、运行测试、编辑文件等工具中选择下一步，或判断某个工具结果是否仍然与任务有关。

Claude Code 的 Jev 压缩插件就是这一类：它让 Jev 判断历史工具调用是否还应保留，再对调用和结果进行保留、截断或删除。参考：[fast-jev-compaction](https://github.com/tamaratran/fast-jev-compaction)。

### 3. 安全和审核门

例如判断请求是否越权、内容是否需要人工审核、输出是否符合发送条件。低置信度时由代码暂停自动流程，而不是让模型自行决定所有后果。

### 4. 高并发分类与评分

例如邮件分类、工单优先级、商品归类、线索评分、文档标签和批量数据筛选。这些任务通常答案集合有限，单次判断逻辑重复，适合使用结构化结果。

## 不适合的场景

- 开放式聊天、长文写作、代码生成；
- 需要模型自己提出未知答案或自由探索的任务；
- 需要详细解释、推理过程或自然语言摘要的任务；
- 选项集合无法提前定义的任务；
- 不允许错误且没有人工复核的高风险决策。

## 最终理解

Jev 不是 Claude 或 GPT 的廉价替代品，而是放在软件流程中的“判断函数”：

> Claude/GPT 负责生成内容，Jev 负责在有限选项、评分标准或真假判断中快速给出机器可执行的决策。
