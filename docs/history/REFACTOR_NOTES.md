# JEV 重构与验证记录

完成日期：2026-09-21。这是桌面版完成前的 Web 重构历史记录；后续桌面功能和验证见 [desktop/VERIFICATION.md](../../desktop/VERIFICATION.md)。使用 Windows 原生进程，没有调度 Docker、WSL 或虚拟机。原业务文档与含原文的评测输出保留在本机，不随仓库发布。

## 已处理的问题

| 原问题 | 当前实现与验证 |
|---|---|
| 使用分块序号冒充 Word 段落号 | 保留正文实际段落计数（包含空段落），表格用行号、PDF 用页码和坐标；长段落切片保留精确字符范围 |
| 文档图片缺席检索 | 本地 RapidOCR + 固定且校验过的 PP-OCRv4 权重；80 处图片均得到转写，可核对图片 |
| 同一 Word 文本框被读取两次 | AlternateContent 只读一个显示分支，排除兼容备用节点；当前原文单元从 310 调整为 307 |
| 表格与正文顺序、嵌套单元格文字遗漏 | 顺序遍历正文 XML，保留行级来源，包含嵌套表格文字、页眉页脚和注释文本 |
| 切换路径就破坏旧索引，上传文件混库 | 独立目录库、内容寻址原始副本、SQLite 不可变快照，构建成功后事务切换 |
| 取消选择仍扫描、索引不可取消 | 选择器只返回路径；扫描后台执行，可取消，失败和取消均保留旧版本 |
| 全文链接不能定位结果 | 内置阅读器显示命中段落和上下文，支持版本化深链接、字符高亮与完整文件下载 |
| 模型只读前缀、候选被硬截断 | 长来源完整切片，问题超限明确报错；所有请求候选分批评估，每批都有 none，包括仅剩一个候选的批次 |
| 候选都被当作证据，引用与答案数量不符 | none 与关键词覆盖共同筛选，去掉同段重复切片和重复原文，引用只对应最终结果 |
| 概率被当作事实置信度、伪冲突/远程调用统计 | 去掉无依据指标，不跨批比较 softmax；诊断只显示实际计数和执行结果 |
| CPU 运行依赖手改下载脚本 | 项目内实现 checkpoint 兼容决策头；严格本地加载，CPU FP32 已验证，数值公式单测通过 |
| 备用静态页缺少挂载、仍用旧接口 | 挂载 /static，重写基础页面，实测原文查询和定位可用 |
| 旧说明与命名残留 | 重写 README 和 env 示例，补充真实评测，研究稿标明历史/架构讨论，项目命名统一 JEV |

## 前端方向与技能

使用已加载的 frontend-design，另通过官方安装脚本把 [Vercel web-design-guidelines](https://github.com/vercel-labs/agent-skills/tree/main/skills/web-design-guidelines) 安装到项目 .skills 并读取。审查使用其上游 [Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines/blob/main/command.md)。

界面以文档核对为中心：左侧管理目录，中间输入问题和阅读摘录，右侧核对原文。色彩采用纸白 #FFFFFF、冷灰 #F5F7FA、正文蓝灰 #182B46、操作蓝 #355BF5、辅助文字 #576B86；品牌使用 Bahnschrift，中文正文使用本机微软雅黑，数字和路径用 Cascadia Code/Consolas。无需联网字体。

签名元素是摘录侧边的蓝色标记与阅读器中的来源高亮。界面包含目录切换、后台进度、取消、导入、文件筛选、移除确认、无答案状态、复制与下载。OCR 转写明确标注，并保留原图核验入口。窄屏采用主动打开的阅读器，不在检索结束时覆盖结果；限制焦点、支持 Escape 关闭并返回触发控件。

## 验证证据

- 19 项 Python 回归测试通过：真实来源定位、Word 兼容节点、图片占位、PDF 页码、长段落不丢字符、多目录隔离、取消/失败保护、历史原文、上传文件名和字节完整性、单候选 none、全部候选处理、决策头数值公式、超长输入、接口与来源限制。
- npm run build 通过。最终 React JS 约 256 KB（gzip 80 KB），CSS 约 26 KB；已移除未使用的 Ant Design 依赖。
- 真实模型在禁止 socket 连接时完成 12 道回归题：8 道有答案题首条命中，4 道无答案题不返回证据；这些题参与了规则修正，不是独立 benchmark。公开复现方法见 [evals/README.md](../../evals/README.md)，不包含原业务题集。
- 当前 9 份文档的索引重建也在禁止 socket 连接时完成。最终共 387 个可检索单元：307 个原文单元、80 处 OCR 转写，未识别图片和解析错误均为 0。覆盖完整不代表 OCR 逐字正确。
- 浏览器实测：桌面 1280×720，390 像素宽的窄屏；无横向溢出。检索命中、来源高亮、原文深链接、文件筛选、Ctrl+K、设置、目录取消、无效路径提示与焦点返回均通过。
- 页面实际切换至 tests/ui-library，文档库仅显示该目录的一份文档；查询“资料室开放时间”命中其第 3 段，未混入其他目录内容。之后恢复原目录并清理测试库元数据，保留测试夹具文件。
- 页面把候选数设置为 20 后，检索详情显示召回 20、模型检查 20、返回 1；成功找到 TokenPocket 截图中的“已安装”。
- 基础备用页面实测成功返回每日收益原文并打开阅读器；检查了完整原文件下载的 SHA-256 与存储元数据一致。没有读取或改写源目录中的原文件。
- 依赖测试客户端有一条 Starlette/httpx 弃用提示，不影响此次通过结果。CUDA 分支、系统原生目录选择窗口的真实鼠标操作以及更大规模文档集未进行自动化验证。

## 仍需明确的能力边界

当前是本地证据检索工具。公开 NanoJev 权重训练于游戏决策，本次没有证明其优于 BM25；实际首轮直接重排反而退化，因此最终使用词法优先的保守排序。相近主题的误匹配、同义表达漏检、跨段组合问题与跨文件冲突仍不能保证正确处理。CPU 推理本轮中位耗时约 12 秒，首次加载更久。

历史快照与原始副本持续保留，尚无自动空间清理。复杂 Office 对象、公式、修订、特殊编码和复杂 PDF 布局仍需结合警告核对原文件。后续应使用独立的中文相关性数据评估/训练决策头，而不是提高界面上的“置信度”显示。
