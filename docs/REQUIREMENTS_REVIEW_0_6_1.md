# 0.6.1 需求复查与修复

复查范围：main 桌面版、cli 服务版、共享检索核心、管理与查询页面、发布包和部署文档。仅使用本地社区 NanoJev 与 OCR，返回原文，不增加生成模型、embedding 或云端 API。

## 需求对应

| 需求 | 实现与验证位置 |
| --- | --- |
| Electron 可开关 Web，高位默认端口 | 设置默认关闭，18766，可选择仅本机或局域网；`DesktopSharing` 与 Electron UI 验收 |
| Web 仅查询桌面当前文档库 | 独立 FastAPI 路由白名单，未提供目录、上传、下载和管理接口；切换当前库会撤销在途旧查询 |
| cli 不使用 Electron，启动两个端口 | `server.py` 启动管理 18765、查询 18766，独立地址与端口，可执行目录不含 Electron |
| 默认管理员、登录、改密 | admin / Jev-Change-Me-2026!；首次强制改密，PBKDF2，CSRF，改密撤销旧会话 |
| 管理员控制文档、目录 | 多目录扫描，按文档保存访问范围；全部选中只适用当前快照，不自动开放后续更新 |
| 查询端不暴露目录，只返回结果 | 只返回文件名、来源位置、原文；目录树、清单、完整文件、内部路径与模型诊断均无接口 |
| 原生 Windows 和 Linux 二进制 | Windows 2022 / Ubuntu 22.04 runner 编译、CPU 真模型和 OCR、表单与重启验证 |
| 本地 CPU 可用 | 发行程序固定 CPU FP32，权重原样复用；不需要 GPU、API Key 或联网推理 |

## 本轮修复

- 查询取消后由实际 CPU 工作线程释放并发名额，防止取消请求形成后台推理堆积；桌面共享重启继续使用同一限流实例。
- 停止共享时先撤销结果，再在状态锁外等待线程退出，避免查询结束与停止监听互相阻塞。
- POSIX 设置 SO_REUSEADDR，允许连接结束后的同端口快速重启；Windows 保留排他监听，两平台都拒绝占用活动端口。
- CLI 退出先停止服务、取消并等待索引任务和查询线程，最后释放数据目录锁；避免后续实例与旧线程同时写入。
- 管理请求支持完整的 5,000 文档授权批次；管理请求上限 16 MiB，查询请求保持 64 KiB。
- 管理员会话使用实例独立 Cookie；排队的写操作在工作线程内重新鉴权，与改密、退出原子互斥。
- 持久化凭据和发布范围做结构及索引引用校验。损坏时明确拒绝启动，保留原文件，不恢复成默认密码或隐式扩大授权。
- 模型检查涵盖 NanoJev 与 OCR；缺少文件时 `--check` 返回非零退出码。远程管理代理来源必须为 HTTPS。
- 修复 Electron 初始共享设置读取失败不显示错误；新增重新加载入口。管理页面明确标识未开放的新索引版本；查询后刷新服务可用状态。
- 打包工具支持复用未改变的模型和运行时文件，同时防止更新新包改写旧包的硬链接内容。

## 验证证据

源码回归、原生二进制、真实 CPU 推理、OCR、重启和 UI 操作分别验证。原生构建工作流会输出可审查的 JSON 报告与截图，随修订发行版提供。最终构建结果见 Release 验证记录，不能以源码单元测试替代二进制验证。

## 仍有的产品边界

社区 NanoJev 使用游戏决策权重，词法召回主导，没有经过企业语义召回率评测。本轮修复不构成检索质量或高并发容量认证。只返回可支持问题的原文，不生成总结。查询端共用一份开放范围，没有终端用户账户、SSO 或部门权限；通过企业网络或认证网关控制访问人群。已返回给用户的内容不能远程收回。

源码 `app.py` 的 8765 是显式供开发者使用的本机管理工作台，不是交付查询入口。发行 Electron 的私有工作台使用随机端口和临时令牌；查询用户使用独立 18766。原有本机工作台、私人文档和索引不在本轮替换范围。

升级程序时保留 JEV-models、JEV、JEV-data / server_data；程序与运行时使用同一版本，CLI 保留整个 _internal。首次部署复用 v0.6.0 的原始模型包，不需要重新下载模型。Windows EXE 未签名；Linux 以 Ubuntu 22.04 x86_64 为构建基线。
